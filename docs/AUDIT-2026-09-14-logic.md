# Logic and usability audit — 2026-09-14

This is the written form of a page I shared with the owner, set down here for Lane 1. What was audited: `docs/scope-and-acceptance.md`, `docs/DECISIONS.md`, and the code on `main` after today's merges of #79, #73 and #77, read against what CORWADO signed and the amendment the owner recorded on 11 September. It was read by five readers, one per audience — a buyer, a farmer, an extension officer, a supervisor, an administrator — each asked whether the application makes sense to the person who will use it. The count that follows (19 blockers, 58 major, 30 minor, with findings that appeared in more than one report counted once) is a scale, not an inventory: treat it as the size of the gap, not a checklist of exactly a hundred and seven things.

## Five root causes

Five decisions explain most of the hundred-odd findings. Fix these five and the majority of the individual items resolve or shrink. Each is a logic decision before it is a code change.

**1. A farmer web app is built on a data model where farmers have no account.** The contract says farmers are reached by SMS and do not use the system. The 11 September amendment puts a farmer web flow in scope, on the owner's reading, pending CORWADO's written confirmation. The code shipped the screens without the foundation: no farmer principal, no farmer routes, no persistence. Farmer "login" is a browser cookie holding a fixture id, and nothing a farmer does is saved.
**The fix.** One decision, in writing from CORWADO. Either farmers are a web audience — in which case Lane 1 builds the farmer principal (an auth user linked to the farmer row), the four farmer routes, per-listing consent, and the screens stop reading fixtures. Or farmers stay an SMS audience — in which case the farmer web surface comes off production and the marketplace becomes staff-entered introductions, which is what the Inception Report's deliverable (g) already says.

**2. A buyer is nobody, and the farmer's phone is on the page.** Buyers hold no account, by decision on 9 September. That is fine, but it means a buyer cannot be identified, so the design chose option 2: a contact request that CORWADO passes on and the number never leaves CORWADO. The code built option 1, the one the documents call irreversible: the farmer's legal name and registration phone printed three times on a public page, with call and SMS buttons. The scope also says the marketplace must not be reachable without a staff session until CORWADO answers the phone question. Today it is the front door.
**The fix.** A buyer is identified by what they give at the moment of interest, not by an account. Replace the phone buttons with a contact request form: buyer's name, phone, what they want, how much. It writes a record, routes to the officer whose caseload holds that farmer, and the officer makes the introduction and records it. That record is deliverable (g). The listing shows a trading name the farmer chose, never the legal name. Until CORWADO confirms this in writing, put the marketplace behind the staff gate or a flag that defaults off.

**3. Half-live screens print fixture facts beside real rows.** Seven flags switch seven groups of screens between fixtures and routes. In any half-on state a screen shows an invented value next to a real one: every live farmer reads as "Self"-registered because the officer lookup is a fixture; every live farmer shows a green "Synced" chip because an empty fixture list means synced; the review queue prints "no farm mapped" for farmers it never asked about; the dashboard is entirely invented and has no live path at all.
**The fix.** A rule, applied everywhere: when a route does not serve a fact, the screen says "not available", never a fixture value. Collapse the seven flags to one per deployment. Give the dashboard its live source, the reports summary route, which already returns exactly its figures.

**4. Every "the person is told" moment has no channel behind it.** A farmer is verified, rejected, merged, reassigned; a listing is withdrawn with a reason; a resource is published "to phones"; a buyer is interested; a password needs resetting. In each case the copy promises a message, and no message can be sent. There is no SMS system, no inbox, no notification table. Staff withdrawal reasons are written to the moderator's own browser tab and vanish when it closes.
**The fix.** Build deliverable (n) as the one channel: a message table, a provider, templates per event, a delivery log, and consent to be messaged recorded at registration. A minimal in-app inbox for staff covers the rest. Until it exists, the copy must not promise delivery, and every reason a person is forced to type must be stored somewhere they can find again.

**5. The officer mobile app does not exist, and three modules assume it.** Farm mapping accepts writes only from an officer on a phone. Offline sync serves a phone. The library "reaches officers on their next sync". Officers cannot even sign in to the web portal, because the login page takes an email and an officer's account is keyed by a derived address nobody types. The Flutter app is an empty folder.
**The fix.** Decide the officer's device for this phase. If the app is coming, Lane 1 builds it and the web copy says "officer app, coming". If it is not coming this phase, the web must become officer-capable: sign in by phone number, a web boundary capture that accepts a walked track or a typed ring, and a resource download link. One of the two, not the current neither.

## Findings by module

### Marketplace and buyers

- **BLOCKER — The marketplace is public while the scope forbids it in writing.** The site root redirects to the marketplace and no session is needed, though the scope says no listing is readable outside the four staff roles until CORWADO answers the contact question, and nothing records that answer. `app/page.tsx · lib/auth/paths.ts · scope-and-acceptance.md "Until CORWADO answers"`. Fix: gate the marketplace behind the staff session, or a flag that defaults off, until the written answer exists in DECISIONS.md, then open it with the contact request in place, not before.
- **BLOCKER — The listing publishes the farmer's legal name and registration phone.** Given and family name on every card and product page; the phone printed in text, as a call button, an SMS button and again in a sticky mobile bar; there is no trading-name field at all. `components/listings/ProductPage.tsx · ListingCard.tsx · components/farmer/ListingForm.tsx`. Fix: add a trading name asked as "What should buyers call your farm or stall?", render only that, and remove the phone from every public surface.
- **BLOCKER — A buyer has no identity and no way to be answered.** No buyer record, table, session or form exists; the only action is dialling, so nothing records that a contact happened and deliverable (g) is not produced. `grep for contact_request, inbox, enquiry: zero hits`. Fix: a contact request form (buyer name, phone, what and how much) that creates a record routed to the farmer's caseload officer, who marks it introduced, declined or no answer; add a farmer "Requests" tab once a farmer principal exists.
- **BLOCKER — Per-listing publication consent is specified and absent.** The amendment requires a revocable consent record at the moment of listing, with its own text version and language; the form has no consent step and writes no record, so "List it" publishes a name and phone with no consent event. `lib/farmers/listings.ts validateListing · ListingForm.tsx persist()`. Fix: a consent screen before publish, in the farmer's language, stored as a second consent row beside the registration one; withdrawing it unpublishes. The consent table already supports this without a schema change.
- **MAJOR — A farmer's own "list it" or "withdraw" never reaches the marketplace.** The farmer account and the marketplace each hold their own copy of the listings, so a publish does not appear and a "sold" mark stays live and contactable. `lib/farmer-session.ts · components/market/marketplace.ts reads the static LISTINGS`. Fix: one source of truth, the listing table behind a route read by both surfaces; resolves with root cause 1.
- **MAJOR — A withdrawal reason is typed by staff and seen by nobody.** The moderator must give a reason, the copy says the farmer sees it, but it is written to the moderator's own session storage and the farmer's screens never read it; any visitor can also switch the public status filter to "withdrawn" and read taken-down listings. `components/market/moderation.tsx · Market.tsx status filter`. Fix: withdrawal is a server write with the reason in the audit row and on the listing, shown to the farmer; the status filter is staff-only; a farmer cannot self-reverse a staff withdrawal.
- **MAJOR — An anonymous buyer is served the staff marketplace, scoped to one state, in English.** "Not a signed-in farmer" is treated as "staff": the read-only scope filters listings to Central Equatoria, the staff status filter is shown to the public, and the language is hard-coded so the switch does nothing. `components/market/MarketPages.tsx · StaffMarket.tsx`. Fix: a third mode for anonymous buyers — listed produce only, all states, the buyer's chosen language, no staff controls.
- **MAJOR — Price sorting compares a litre of milk with a bull.** Price filter and sort compare the bare number regardless of unit, quantity sort has the same defect, listings never expire and quantity never decrements, and a sold listing can be relisted at its original quantity. `components/market/marketplace.ts applyFilters, sortRows · ListingForm status machine`. Fix: normalise to price per kilogram or per unit class before comparing and scope the price filter to a unit; add a 60-day expiry with a farmer "extend"; relisting from sold asks for the remaining quantity.
- **MAJOR — Contracted market prices do not exist.** Deliverables (f) and (h) are "Included" but there is no price board, reference price or table; the only prices are farmer asking prices in SSP with no date and no market name. `data-model-extension.md market_price · no route, no screen`. Fix: a price board fed by the administrator's manual entries, each with market name and collection date, shown beside the asking price; the data-model note says never a bare figure.
- **MAJOR — Trust signals are decorative, and stock photos pose as the produce.** "Verified sellers only" can never change the result because unverified farmers cannot publish, every listing shows a Wikimedia stock photo as its own with no placeholder mark, and there is no report or abuse path for a scammed buyer. `lib/farmers/listings.ts listingCover · public/crops/CREDITS.md`. Fix: show what "verified" means (by an officer, on a date), label stock images as illustrations or show the honest empty frame, and add a per-listing "Report this listing" that reaches the caseload officer and is recorded.
- **MINOR — Buttons that go nowhere.** "Contact seller" reopens the same page, "View seller's listings" goes to the unfiltered marketplace, nine category links all go to the same unfiltered page, and anonymous buyers see a "Your listings" badge leading to a farmer-only route. `ListingCard.tsx · MarketDetail.tsx · ShopMasthead.tsx`. Fix: contact seller opens the contact request, seller's listings filters by seller, category links carry the category, and farmer controls are hidden from anonymous visitors.

### The farmer side

- **BLOCKER — No farmer account exists; sign-in is a cookie holding a fixture id.** The farmer table has no link to an auth user, the session file says it is a preview to be replaced, and anyone who sets the cookie to a fixture id is signed in as that farmer with no password. `lib/farmer-session.ts · prisma/schema.prisma Farmer`. Fix: root cause 1 — an auth user per farmer linked by id, a server session, the farmer routes, sign in by phone and password with the phone derived the way officers already are.
- **BLOCKER — Self-registration writes nothing, and the live route cannot represent it.** Register stores the farmer in React state and loses it on reload; the only live create route is officer-only and hard-codes the source as "officer"; no code assigns a self-registration to an officer by payam or approves it. `farmer-session.ts register() · api/farmers/route.ts`. Fix: a farmer-side create route that writes the row as pending with source "self", assigns the caseload officer by payam, records consent, and excludes the farmer from reach until an officer approves; the queue shows self-registrations as a distinct kind.
- **BLOCKER — Every fixture farmer shares one password, and their phones are public.** The fallback password for every fixture farmer is a literal string and their phones are printed on the public marketplace, so reading a phone signs you in as them; the people are invented, but the site presents them as real. `lib/fixtures/farmers.ts FARMER_FIXTURE_PASSWORD · farmer-session.ts passwordOf`. Fix: real accounts with real hashed passwords, or no farmer sign-in on production; no fixture credentials on a public domain either way.
- **MAJOR — An officer-registered farmer can never sign in; a self-registered one never exists.** The officer intake sends no password, the self-registration sets a password but writes no row, and the intake offers a "Self-registered" option that is silently discarded. `components/farmers/RegisterFarmer.tsx · packages/shared/src/farmer.ts`. Fix: one farmer record, two ways in — officer intake creates the account (initial password or an SMS one-time code once (n) exists), self-registration creates the same record as pending; drop the "how registered" control from the staff form.
- **MAJOR — Password reset and lockout both point at a process that does not exist.** "An extension officer or CORWADO can reset it for you" is plain text with no link, name or number; no officer screen resets a farmer password; the five-failure lockout is React state that clears on refresh and the locked farmer sees disabled fields with no way forward. `components/farmer/FarmerLogin.tsx · i18n login.forgotBody`. Fix: reset by the caseload officer from the dossier, recorded in the audit log, the new password handed over in person or by SMS code; lockout enforced on the server; the locked screen says who to contact and how.
- **MAJOR — Phone is the only login key, and it is not unique.** Sign-in matches on phone and returns the first farmer found, so a shared household phone locks out the second person and opens the wrong record for the first; no OTP exists and the self-registration form never collects a national ID. `farmer-session.ts signIn · schema Farmer.phone has no unique constraint`. Fix: login by farmer number plus password, phone as a recovery channel not the identity; each person keeps their own farmer number; ask for a national ID where one exists, optional.
- **MAJOR — Registration consent does not cover a public marketplace.** The consent text says details are shared "only with the officers and partners running this programme" while the marketplace publishes them to anyone, and the self-registration discards the consent it collected (no record, version or language). `i18n consent text · farmer-session.ts makeSelfFarmer`. Fix: two consents, both recorded — registration consent at sign-up and publication consent per listing; the 12 September CORWADO authorisation that the disclaimer covers listing still needs the trading-name and contact-request design to be true, because the disclaimer never mentioned a phone on a public page.
- **MAJOR — A rejected farmer is told to do two things they cannot do.** "Contact your local CORWADO officer, or change your details and ask to be checked again" — but no officer name or number is shown, the account page edits only password and phone, and there is no "ask to be checked again" control. `components/farmer/FarmerOverview.tsx · FarmerAccount.tsx`. Fix: show the rejection reason, the caseload officer's name and phone, editable identity fields, and a resubmit button that calls the existing resubmit route.
- **MAJOR — Arabi Juba is two strings, and the page mirrors English text right-to-left.** The Arabi Juba dictionary holds two keys of about four hundred; choosing it flips the layout right-to-left and marks the page as Arabic with English words; validation errors are hard-coded English outside the translation system. `lib/i18n/ar-juba.ts · lib/farmers/schema.ts`. Fix: hide the language option until CORWADO supplies the strings and settles the script question, and route every error message through the translation function so nothing is missed the day the strings arrive.
- **MINOR — Three account tiles lead to the same page; "Your verification" has no verification on it.** Security, Language and Verification tiles all open Settings (record, language, password, phone, sign out), and photo uploads produce listings whose images are guaranteed broken because the temporary URLs are revoked on save. `FarmerOverview.tsx tiles · ListingForm.tsx blob URLs`. Fix: a verification card showing status, what it means and the officer; photos uploaded to storage through a signed grant before the listing saves.

### Farm mapping

- **BLOCKER — Every mapping write requires an officer on a phone, and there is no phone.** Creating a farm, adding a boundary and declaring crops are officer-only routes with the officer a foreign key to the officer table, so an admin is refused by role and by the database; the only client is read-only and the mobile app is an empty folder, so no farm can be mapped by anyone today. `api/farmers/[id]/farms · api/farms/[id]/boundaries · apps/mobile/.gitkeep`. Fix: root cause 5 — a web capture for officers that accepts a walked GPS track uploaded from a phone's browser or a typed ring, until the app exists; the validation already runs on the server.
- **MAJOR — No overlap, containment or size sanity check.** Self-intersection is caught and area is computed correctly, but two farms may share the identical ring and be counted twice, a polygon anywhere on Earth is filed under the farmer's payam unchecked, and a 50,000-hectare smallholding inserts cleanly into the area totals. `lib/api/geometry.ts · farm migrations`. Fix: at insert, intersect against other current boundaries, test the centroid is inside the farmer's payam, and flag an area outside a plausible band for supervisor review rather than refusing outright.
- **MAJOR — A supervisor reads "No boundary walked · ±0 m" for a mapped farm.** Geometry is withheld from supervisors by design, but the client fills the withheld fields with zeros, so the screen renders the absence of a permission as a fact about the land. `lib/farms/api.ts toFarm · components/farmers/Boundary.tsx`. Fix: say "Boundary not shown at your access level" and omit the accuracy row; the state map route exists for supervisors and has no screen — build that screen.
- **MAJOR — Re-mapping and crop changes are invisible to sync, and uncorrectable once the officer leaves.** The farm's updated stamp only moves when the farm row itself changes, so a device syncing since a date never learns of a new boundary or crops; only the caseload officer may re-map, so if the pointer is empty or the officer is deactivated the only path is delete and recreate, losing the history the versioning exists to keep. `farm_set_updated_at trigger · boundaries route inCaseloadOf`. Fix: touch the farm row on boundary and crop writes, and allow an admin to re-map on behalf of a named officer, recorded as such.
- **MAJOR — "Season" is a label with no calendar.** A season is a year plus "main" or "second" with no dates and no current season; "9999-main" validates; a typo creates a phantom season in the area report; the names are placeholders until CORWADO confirms local ones. `packages/shared/src/farm.ts SEASON_PATTERN`. Fix: a season table with start and end dates per state, a computed current season, and the local names from CORWADO; forms default to the current season and refuse a future one.

### SMS and notifications

- **BLOCKER — Nothing can send a message, and twelve moments in the product assume one.** No provider client, send function, queue, template, delivery log, opt-out or message table exists; the only "SMS" in the code opens the buyer's own phone; meanwhile a self-registration promises "an officer will check your details", a rejection names no officer, and a verification, a merge, a reassignment, a visit follow-up and a published resource all tell nobody, while a new staff member's password is typed by the administrator and must be handed over by other means. `grep sms|notif across apps, packages, prisma: no capability · i18n register.doneBody, account.whatRejectedBody`. Fix: deliverable (n) as designed — a message table with status, segment count and cost, an approver before any campaign sends, templates per event in both languages, and a delivery log the reports can read; until it exists, every string that implies delivery names the real channel ("your officer will tell you", "the administrator gives you your password in person").
- **BLOCKER — The consent farmers gave does not cover being messaged, and the only opt-out cannot be written.** The consent text covers recording and connecting, not messaging, names no channel and offers no way to decline messages while staying registered; the consent row has no purpose or channel; Bird lists two-way SMS as unavailable for South Sudan so a STOP keyword cannot be received, the only opt-out is an officer withdrawing consent, and no route writes the withdrawal field, so the dossier renders a "Withdrawn" row nothing can populate. `i18n consent.body v1.0 · prisma Consent · PR #76 two-way note`.
